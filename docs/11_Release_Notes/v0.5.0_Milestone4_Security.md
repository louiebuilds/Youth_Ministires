# Release Notes — v0.5.0

**Release date:** 2026-07-23
**Milestone:** 4 — Security
**Status:** Complete

---

## Highlights

Version 0.5.0 establishes the detailed application and database authorization
boundary for the Youth Ministries Platform.

---

## Added

- Final five-role permission model
- Active-account lifecycle enforcement
- Centralized typed application capabilities
- Active profile and role loading during server authorization
- Role-aware desktop and mobile navigation
- Server-side guards on every platform route
- Private database authorization helpers
- 19 role, relationship, assignment, and audit RLS policies
- Parent household and explicitly permitted student access
- Event-scoped volunteer access
- Published-event access for parents
- Read-only audit oversight for approved roles
- Threat model and incident-response process
- Administrative access review and security test standards
- PII rules for accounts, households, and students
- First-name and last-initial student display formatter
- Automated and Product Owner security acceptance tests

---

## Security

- Registration cannot self-assign privilege.
- Inactive application profiles cannot enter protected routes or read
  protected data.
- Parents cannot browse unrelated households or students.
- Event assignments do not expose general student information.
- Unauthorized route requests fail without exposing policy details.
- Authenticated roles cannot insert, update, or delete audit records directly.
- General student labels do not expose full last names.
- Full student names require an explicitly authorized operational purpose.

## Deferred Scope

Storage, audit ingestion, user-management workflows, ministry feature data,
exports, production monitoring, backup exercises, and production incident
procedures remain assigned to their later approved milestones. Their absence
does not grant access.
